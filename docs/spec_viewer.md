## 現行仕様(まとめ。食い違うときは、ここが基準)

### ビューア(index.html)

- **BADGE機能の削除**: 「機能ごとの詳細メモ」の「BADGE機能の削除」のとおり。ヘッダー右の「<」も無くなり、ICON・TODAYは直接表示する。
- **ヘッダー固定(🔓/🔒)**: 固定中は、ヘッダーとデータ部の間のラインを、アクセント色の2pxにする(1pxの線+下に1pxの影。レイアウトは動かない)。色は滑らかに変わる。固定の状態は `<head>` 先頭の小さなスクリプトが `html.hdr-locked` として先に付ける(起動時に青く光らないようにするため。起動中の間は色の遷移なし)。
- **タップハイライト**: スマホで丸いボタンを押したときの四角い残像を消すため、全要素で `-webkit-tap-highlight-color: transparent`。押した感触は `:active` の暗転が出す。
- **括弧の前後の空き**: 表示するときだけ、タイトル・データ文(PCは`display_pc`、スマホは`display_sp`、なければ`title`)の括弧 `「」『』【】()()` の前後に半角スペースを足す(`spaceBrackets`)。データは変えず、検索・照合には影響しない。
  - 足さない: すでに空白(全角含む)があるところ / 括弧どうしが並ぶところ(閉じ括弧と閉じ括弧など。閉じ括弧と開き括弧の間は足す) / 閉じ括弧の後ろが 、。,.!?・:;(全角の,.:;を含む) / 行頭・行末の外側 / 開き括弧の前が上の記号のとき。
  - `【】` の前が全角スペースのときは、前に足さない(後ろは足す)。
- **snsポップアップの Fancam**: 「機能ごとの詳細メモ」の「sns の Fancam を種類(SNS)ごとにまとめる」のとおり(種類名は常に表示、開いたときは「▲」の右、「+N」は幅40px固定で3桁以上は文字を小さく)。
- **snsの type 補正(表示)**: `type` が `site` / `etc` / 空でも、URLのドメインがXなどと判定できるリンクは、その種類の行に移して表示する(データは書き換えない)。
- **動画ポップアップ**: 下端のTAGスイッチを再表示。ON/OFFは `vidTagMode` に保存して、次に開いたときも引き継ぐ。
- **楽曲バー(♪)**: 右端に披露実績📊を常に表示(曲が読み込まれるまでは非表示)。押すと表示中の曲の披露実績を開く。
- **披露実績アイコンの条件**(セトリ・アルバムのポップアップの各曲): **songs.json にある曲だけ表示し、披露が0件でも表示する**。無い曲は出さず、同じ幅の空きにする(songs.json未取得の間だけ従来の判定)。曲名の一致は披露実績の集計と同じ正規化(NFKC・大文字小文字・空白を無視)。
- **vocalの表示**:
  - 楽曲バー: `曲名 / artist vocal`(artistとvocalは半角スペース区切り。vocalが無ければ従来どおり)。
  - アルバムのポップアップ(収録曲)と動画ポップアップの見出し: 曲名のあとに半角スペース+少し小さい文字(0.85倍・サブ色)でvocal。アルバムの収録曲は、曲名とアルバムのartistでsongs.jsonから探す(artistが違う同名曲は別の曲)。
  - セトリのポップアップ・披露実績のポップアップ: vocalは出さない(セトリは入力されたartistのまま)。
  - vocalでの検索は、今のところ対象外(あとで考える)。
- **キーボード(PC)**: TODAYモードのとき、`←`=前日、`→`=翌日(フリックと同じ向き・同じスライド)。押しっぱなしでは、動きが終わるたびに次の日へ進む。入力欄・スライダー・ポップアップ・カレンダーが開いている間、Alt/Ctrl/Cmd/Shiftを押している間は動かさない。
- **3回タップ(隠し機能)**:
  - 発動条件: 年・月・日・曜日・時刻のボタン、📍、📋、💞、🏷️、💽、🔗がすべてON(♪は条件に含めない)。
  - データ部の日付・時刻を3回タップ(PCは Ctrl/Shift/Cmd+クリック): 📋セトリ検索がOFFならlogidで `#logs`、ONならsetlistidで `#setlist` をhelperで別タブに開く。
  - 上の条件に加えて♪がONのとき、楽曲バーの曲名の行を3回タップ(PCは Ctrl/Shift/Cmd+クリック): `?artist=…&title=…#songs` でhelperを開き、その曲を読み込む。バー右端のボタンは対象外。
- **venue の表示**: venue を持つ行は、タグ行(🏷️)の一番左に会場名のチップを出す(`tags` には含めない)。チップを押すと、その会場名で検索。通常の検索の対象にも含める。記念日の参照行(`ref`)は、元の行の venue・map を引き継がないので、ピンも会場名も出ない。
- **タグ表示(🏷️)**(`createItemNode`):
  - 🏷️ボタン(`#tagToggleBtn`)でON/OFF(`gl_log_tag_mode`)。ONのとき、チップがある行のタイトルの下にチップの段を出す。行の下端、またはチップの段の空いた所を押すと、その行だけ反転する(🏷️ボタンで全体を切り替えるとリセット)。チップを押すと、今の絞り込み(TODAYなど)を解除して、そのタグで検索する。
  - **チップの出し方(上から順に、最初に当たったもの)**: ①venueがあれば一番左に出す。②行の`tags`(前後の空白を除き、空文字・重複は出さない。`tiktok更新`は常に出さない)。③行の`tags`が1つもないときだけ、snsリンクの`tags`から、1リンク内の重複を1回と数え、出現数の多い順(同数は登場順)に最大3つ。④tags・venue・snsのタグのどれもないときだけ、下の「抽出タグ」。
  - **見た目(色ではなく、枠の形と濃さで見分ける)**: 行の`tags`=今のまま(`data-kind="tag"`)。venue=薄い青の地(`tc-venue`)。snsのタグ=地なし・破線(`tc-sns`)。抽出タグ=地なし・点線・文字を薄く(`tc-auto`)。ダークモードでも同じ関係。チップには`data-kind`が付く。
  - **抽出タグ(仮の表示。データは変えない)**: TODAYモードのときだけ、tags・venue・snsのタグがなく、参照行(`ref`)でない行に、1つだけ出す。タグがいつか全部登録されたら、自然に出なくなる。
    - 候補: 読み込み済みのlogs(参照行を除く)の`tags`。1回しか使われていないタグも含む。次は除く: グループ名(Girls²・Lucky²・Laki・iScream。`TAG_AUTO_STOP`)、`tiktok更新`(`HIDDEN_CHIP_TAGS`)、全角半角・空白をそろえて3文字未満のタグ。snsリンクのタグは候補にしない。
    - 一致の条件(A案): タイトル+`display_pc`を小文字にしただけの文字列に、タグが**そのまま**含まれること。全角半角・空白はそろえない(押したときの検索は小文字化の部分一致なので、元の行が必ずヒットする)。英数字で始まる・終わるタグは、その側の隣が英数字(語の途中)なら一致としない(例: KAZ は okazaki に当たらない)。
    - 複数当たるときは、文字数が長いタグを優先し、同じなら使用数の多いもの。
    - 当たらなかったとき(代わりのタグ。`TAG_AUTO_FALLBACK`): contents が DIARY なら「日記更新」、GTUBE なら「Gtube」、GLRADIO なら「がるらじ」。それ以外のcontentsは何も出さない。除外リスト・3文字未満の除外は適用しない。
    - 押したときの検索は、ほかのチップと同じくチップの文字で検索する。代わりのタグは、その語がタイトルに無い行が多く、元の行が結果に出ないことがある(「Gtube」はcontentsが検索対象なので出る。「日記更新」はほぼ出ない)。タグを登録していけば出るようになる。
    - 候補の一覧は、最初の使用時に1回作り、`logs`が入れ替わると作り直す(`tagAutoSrc`)。TODAYを保持して起動したときは、空き時間(`requestIdleCallback`)に先に作る。
    - 負荷: 実データ(約13,000行)で、1行あたり約0.02ms、一覧の作成は数ms。TODAYは年フィルターなしでその日付の行だけ(1日の最大32行)、年フィルターを全ONにしても最大88行。描画は40行ずつ。影響は計測できない程度。
    - 実データでの当たり率(10/27時点、タグなし11,498行): 既存タグの語が当たるのは約13.6%(DIARYは4%、GTUBE 63%、GLRADIO 49%、COLUMN 100%)。残りの大半は、そのタグが他の行に登録されていないもの。
  - 検索の対象には、行の`tags`、snsリンクの`tags`、venueが含まれる(抽出タグは含まない)。
- **MAPピン(📍)の仕様**:
  - 全ての行にピンの部品を作る。表示は MAP ボタン(`#mapToggleBtn`)が ON のときだけ。切り替えは、クラスの付け外しで左からスライドする(再描画しない)。
  - map が Google の埋め込みURL・`<iframe src>` のとき: ポップアップで地図を表示(リンク先は埋め込みの座標から作った通常のURL)。それ以外の `http(s)://` のURL: そのまま新しいタブで開く。
  - map にリンクがなく venue があるとき: ピンは押せる状態になり、会場名で Google マップを検索する URL(`https://www.google.com/maps/search/?api=1&query=…`)を新しいタブで開く。
  - map も venue もない行は、ピンを隠して(幅は保つ)押せない。map が `http(s)://` でない値のときも、押せない(venue があれば検索)。
- **披露実績ポップアップ**: アーティスト名(`.stat-artist`)を出す。
- **動画ポップアップの表示順**(2026-11-26): MV → Dance Practice → Performance → Lyric → Live → Reaction → Call Lecture → それ以外(Other・自由入力。登録順のまま) → Fancam(常に一番下)。typeは大文字小文字と前後の空白を区別しない。同じtypeは1行にまとめ、登録順に番号を付ける。
- **動画ポップアップの Fancam**: 種類が `Fancam`(大文字小文字は問わない)の行のアイコンは、SNS ポップアップの Fancam(カメラ)と同じ絵・同じ表示範囲・同じ線の太さ。
- **ヘッダー・ボタン**: ↺(`#backBtn`)を共有ボタンの左に表示して有効にした。ヘッダーと楽曲バーのボタンを、共有と映像、フォントとダーク・Uta-Net、鍵と披露実績が上下でそろう位置にした。Uta-Net ボタンの幅は、フォント・ダークのボタンと同じ。歌詞ボタン(`.song-lyrics-btn`)は幅56px。
- **TODAY / ICON のボタン**: 幅を TODAY にそろえる(`#iconToggleBtn::after` に TODAY の文字を透明で置いて幅を確保)。
- **FILTER の自動ON を廃止**: ▲/▼ ボタンで FILTER ボタンを自動でONにする動きをやめた(起動時の復元も同じ)。
- **読み込み・表示の最適化**: `songIndex()`(小文字化した曲名の Map と、統計用の Set)で線形の検索を置き換える。`SORT_TITLE_COLLATOR` を `updateDisplay` の外に出す。`makeDataSource` は manifest ベース(`getManifest(force)`、`latest()`、`fetchFresh(info)`、API の sha へのフォールバック、`defer`)。songs・setlist・albums は、logs の描画が済むまで読み込みを遅らせる(`logsStarted`)。`<head>` の先頭スクリプトで IndexedDB の読み出しを早めに始める。
- **アニメーション**: 押したときの縮み(WAAPI の `scale`)、ON にしたときの円形(`clip-path`)の広がり(ユーザー操作から1200ms以内の `is-active` だけ)、ポップアップの `translateY(18px) scale(.96)` からの表示。`MOTION` の変数で速度を調整する。共有のトースト(`#shareToast`)は、下から少し上がりながら出る(opacity と transform だけ)。アニメーションは opacity / transform のみ・0.2秒以内を原則とし、`prefers-reduced-motion` では止める。

## 機能ごとの詳細メモ

見出しの行番号(`### L76` など)は、メモを作成した時点の `index.html` 内の行番号(目安)。

## CSS

### L76
キーボード操作時のフォーカス表示。各所でoutline: noneにしているボタン・リンク・入力欄・role="button"の 要素すべてに対して、マウスクリック時は出さずキーボード操作時だけ共通の枠を表示する(:focus-visible)。

### L88
「PC版サイト」表示時、横幅が広い仮想ビューポートになることで指の縦ドラッグが横パン(2本指的な 自由パン)と誤認識され、縦スクロールが効かなくなることがあるための対策

### L180
文字サイズ「A」ボタン:現在の拡大縮小段階が既定値(0)でなければ青くする。パネルが開いている間は 別途リング(box-shadow)で開いている状態を示す

### L184
ホバー中でもis-active(青)を確実に優先させる。押した直後はカーソルがボタン上にあるため、 これが無いと:hoverの背景色に上書きされ、カーソルが離れるまで青くならないように見える

### L230
SETLISTモード切替アイコン(検索窓の左側に内包)。検索窓の角の丸み(border-radius)にかからないよう、 左オフセットをborder-radius以上確保してから配置する

### L272
コンテンツ種類ボタンの2段目:ボタンをドラッグして下に落とすと現れる。中身が無い間は折りたたんでおき、 ドラッグ中(drag-target-active)だけ薄く広げてドロップ先として掴めるようにする。中身が入ったら(has-items) 通常表示、無くなったら自動的にまた折りたたまれる

### L281
月フィルターは、年フィルターが1つ以上選択されている時だけ表示する。display切替だと一瞬でパッと 出入りしてしまうため、max-height/opacityをアニメーションさせて滑らかに開閉させる

### L305
アイコン表示モード時は、アイコンの文字幅によってボタンごとの横幅がばらつく(多段時に段によって大きさが揃わない)のを防ぐため、 幅・高さを固定して常に同じ大きさの円形ボタンにする

### L314
checkboxは非表示(opacity:0/幅高さ0)にしているため、input自体ではなく見た目上のlabel側に フォーカスリングを出す(inputは0x0でリングが実質見えなくなるため)

### L321
年/月/グループ/メンバーでフィルターした時、実際にはチェックせず、該当データがあるコンテンツ種類の ボタンにだけ「ランプ」を点ける(チェックはしないのでcheckedの::afterとは別に用意する)

### L324
ダブルクリック/ダブルタップで除外指定したボタン:薄い色にして、そのフィルター値に該当するデータが 常に非表示になっていることが視覚的にわかるようにする

### L337
メンバー/グループフィルターホバー時のPREVIEW表示専用アイコン。データ部のteam-icon(11.25px固定)は ハートより小さく見えるため流用せず、ここではハート・四角どちらも見た目の大きさ・名前との間隔を揃える

### L339
メンバー/グループ/コンテンツ種類、いずれのフィルターをホバーした時もPREVIEW内のアイコンが同じ幅の 枠(1em)・同じ間隔(4px)になるようにする専用クラス。アイコンの種類によらず、名前の開始位置が揃う

### L380
文字サイズ変更パネル(「A」ボタン直下に、アイコンに対して中央揃えで表示)。 アイコン下からなめらかに伸びるように、transform-origin:top + scaleY + opacity のtransitionで開閉する

### L459
長押しで「保持」状態にした場合の青いリング。ボタンの内側に描くため、外側に広がらず .header-btn-group の他ボタン(gap:4px)とは衝突しない

### L471
TODAYモードのフリック時に#items(データ行)と#noResult(NO DATA表示)をまとめてスライドさせるための外枠。 レイアウトに影響しないよう幅のみ指定し、余白・装飾は持たせない

### L474
NO DATA表示時、メッセージの表示位置(=NO RESULTS FOUND時と同じ位置)は変えずに、 その下の余白部分だけをフリック可能にするための透明な当たり判定。 position:fixedでドキュメントの流れから外れるため、他要素(updated>やフッター)を押し下げない。 z-index:-1で通常の要素(テキストやボタン)より背面に置くことで、それらのクリック/タップは妨げない

### L498
今日の日付の行を目立たせる(TODAYモード中は全行が「今日」になるため対象外)。 太字にすると文字幅がわずかに変わり右側の要素がずれるため、色だけを変える

### L525
アイコン本体を置く箱。幅を常に固定にして中央寄せすることで、枠(item-contents)の開閉・展開状態に関わらず アイコン自体の描画位置が絶対にずれないようにする(text-alignによる位置ズレを避けるための専用の箱)。 PC通常表示ではコンテンツ名がすぐ右に続くので控えめな幅、アイコンのみ表示(ICONモードON/スマホ)では 枠(28px)いっぱいに広げて、閉じている間も枠の中央にアイコンが来るようにする。

### L544
ICONモードON時はテキストが無くアイコンのみになるため、固定幅にしてどのアイコンでも枠サイズが揃うようにする(PC版・スマホ版で共通の幅)

### L552
コンテンツアイコンをクリックした時、隣に別枠を出すのではなく、このアイコン枠自体を広げて コンテンツ名を表示する(枠の背景・境界線はそのまま)。実際の幅はコンテンツ名の長さに応じてJS側で 計測して都度style.flexBasisに反映する(下のmax-widthは計測前後の保険的な上限)。 アイコン自体は.item-contents-icon側の固定幅で中央寄せしているため、この枠が広がってもアイコンの 描画位置は動かず、コンテンツ名だけがアイコンの右側に伸びて出てくる。 body.icon-only-mode .item-contents (bodyタグ分だけ詳細度が高い)より必ず優先させるため、 同じくbodyを付けて詳細度を揃え、CSS上で後に置くことで確実に上書きする。

### L597
🔗アイコンは行の右端(タイトルの後ろ)に固定する。横スクロールするのはタイトルだけなので、文字をスクロールしてもアイコンは動かず、文字とも重ならない。 通常(🔗ボタンOFF)は幅0で見えない。ON(#itemsに.link-mode)で幅を確保し、右からスッとスライドして現れる(動かすのはtransform/opacityだけなので、行数が多くても軽い)。 OFFにしたときは、スライドして消えた後に幅を解放する(width/marginのtransition-delay)

### L608
G2/L2アイコンを押すと、該当メンバーのハートがタイトル側にアコーディオンのように広がって表示される。 overflow-xだけhidden・overflow-yだけvisibleのように分割指定すると、ブラウザ側でvisible指定がautoとして 扱われてしまい(値が異なる軸ペアの自動変換仕様)、絵文字がline-heightをわずかに超えた際に不要な縦スクロールバーが 出てしまう。そのため軸を分割せず通常のoverflow: hiddenのままにし、代わりにline-heightを絵文字が収まる 高さまで広げることで、下端が欠ける問題を解消する

### L616
both(G2/L2混在)の行のみ、各グループの先頭ハートの左下に色付きバッジを重ねて表示する。 ハート自体の位置・幅には影響しないため、四角の有無でハートの並びがずれない

### L683

### TODAYモードの高さ計算(updateItemsMinHeight)

`#items`の`min-height`を「画面の残り高さ」まで動的に伸ばし、表示件数が少ない日でも画面全体でフリック判定を効かせる仕組み。

```js
const docTop = itemsEl.getBoundingClientRect().top + window.scrollY; // ドキュメント基準に変換
const extra = window.innerHeight - docTop;
itemsEl.style.minHeight = extra > 0 ? extra + 'px' : '';
```

`getBoundingClientRect().top`はスクロール位置に依存するため、`window.scrollY`を足してスクロールに左右されない値に変換している。これを怠ると、何らかの理由でページがスクロールされた状態で計算が走った際に異常に大きい値が固定化され、「update/HELP/SETTINGが画面のかなり下に表示される」症状が起きる(実際に発生し修正済み)。

副作用として、モバイルでのピンチ/ダブルタップによるページズームは`window.innerHeight`を異常値にするため、viewportに`maximum-scale=1.0, user-scalable=no`を指定してズーム自体を無効化してある。

### 検索窓の日付入力によるTODAYモード(searchDateTodayActive)

`20251002`等の8桁日付を検索すると、その日を対象にTODAYモードへ自動的に入る。前後日の←→ボタン・フリックも使用可能で、操作した瞬間に検索連動フラグを解除し検索窓をクリアする(表示日と検索窓の表示がズレるのを防ぐため)。

### フィルターの「ランプ」表示(has-data-lamp)

TODAY/セトリ検索モードのどちらでもないとき、年/月/グループ/メンバーの指定または検索ワード確定があっても、コンテンツ種類ボタンの絞り込み自体は変えず、該当データがあるボタンの右上に黄色い点だけを表示する。実際にチェックをON/OFFする(絞り込みに反映する)のはTODAY/セトリ検索モードのときだけ。

### SNSリンクポップアップ(`sns`属性)

```json
"sns": [
  { "type": "x", "urls": ["https://x.com/p/1", "https://x.com/p/2"] },
  { "type": "instagram", "urls": ["https://instagram.com/p/A"] }
]
```

- 表示順はデータの入力順ではなく固定順: `x → instagram → tiktok → youtube → gl2family → cl → threads → line → radiko → (etc / 未知のtype)`。`SNS_TYPE_DISPLAY_NAMES`のキー順を優先順位として使う
- 各urlは文字列そのものではなく連番(1,2,3…)で表示し、**typeごとに1から**数え直す
- `http(s)`で始まらない不正なURLは番号だけ表示しクリック不可にする(`is-invalid`)
- typeアイコンはSimple Icons由来のSVGパスで単色(`currentColor`)表示。未登録typeは同じ幅だけ空ける

### sticky-header(検索部固定)の注意点

`body`に`overflow-x: hidden`だけを指定すると、ブラウザの仕様で`overflow-y`が暗黙的に`auto`扱いになり、`body`自体が独立したスクロールコンテナとみなされて`position: sticky`が効かなくなる。回避のため`overflow-x: hidden`は`body`ではなく`html`(元々`overflow-y: auto`を指定)にまとめて指定している。

- 位置は`position: fixed`で、リサイズ・スクロールのたびに計算し直す
- 画面の文字は`\uXXXX`のエスケープで書く(後述のBloggerの文字化け対策と同じ流儀。index.htmlでは必須ではないが揃えてある)

### contentsの追加・アイコン変更

- `TELEPHONE`: データ部は`📞 TELEPHONE`。フィルターボタンは無く、フィルター判定上は`FANCLUB`として扱う(`fanclubAliasConts`、`normalizeContType`)。FANCLUBボタンをONにすると表示される

- helperで既存データ(logs / setlist)の項目を空欄にすると、その項目は `!clear` としてIssueに事前入力され、削除チェックなしでmergeが項目(キー)ごと取り除く(対象: logsは time / groups / contents / title / display_pc / display_sp / url / map / setlistid / relations、setlistは title / artist / member / venue / source / songs。tags / sns は従来どおり個別の `-` 指定)。Issueに直接 `!clear` と書いても同じ
- **tagsの順序(logs)**: 新規登録は入力順のまま保存し、表示(🏷️)もその順。helperで既存行のtagsを変更(追加・削除・入れ替え・並べ替え)すると、入力欄の並びそのままの全件を先頭に`=`を付けて送る(例 `=,タグ0,タグ1,タグA`)。merge側は`=`があれば既存tagsをその順で置き換える(入力にないタグは消え、空なら属性ごと削除)。`=`を付けない従来入力(Issueフォームに直接書く場合)は、既存に追記し`-タグ名`で個別削除のまま。変更が無ければ何も送らない。
- `DEBUT`: ⭐、`FORMATION`: ✨ に変更(以前は🎂と🤝)。ボタンは無く、フィルター判定上は`BIRTHDAY`として扱う(BIRTHDAYのボタン🎂をONにすると表示される)
- SNSの`radiko`: アイコンと表示名`radiko`を追加(URLは`radiko.jp`で自動判定)

### フィルターボタンの除外(ダブルタップ)の不具合修正

ボタンを300ms以内に2回押すと、その値に当てはまるデータを常に非表示にする「除外」になり(薄い色)、もう一度ダブルタップで解除する(`excluded`は`gl_log_excluded_filters`に保存)。

**TODAY表示中にグループ/メンバー(G2・L2・YZH・RINなど)を除外・解除すると、データが元に戻らない**不具合があった。TODAY/セトリ検索モードではコンテンツ種類のボタンが自動でON/OFFされるが、除外・解除したときにその再計算(`autoUpdateContentTypeFilters`)を呼ぶのが、コンテンツ種類・年・月のときだけだったため、コンテンツ種類のボタンが古い状態のまま残っていた。現在は、どのボタンの除外・解除でも再計算を呼ぶ。

### index: TODAYモードと検索窓(通常モード)

- （廃止）バッジ: 畳んでいるボタンの右上の選択数。BADGE機能の削除に伴い、現在は出さない。

### 折りたたみの動き(改訂)
- **閉じる:** ① 行のボタンが左端のボタンの位置へ横に集まる(0.3秒) → ② CONTENTSなどで複数段のときは、各段の左端が一番上の段の左端へ縦に集まる(0.22秒) → ③ 左上にひとつだけ残ったボタンが、帯の開閉ボタンへ小さくなりながら吸い込まれる(0.3秒)。③の途中から行が高さ0pxまで畳まれて下が上へ詰まる。集まるあいだ、重なって隠れるボタンは薄くなって消える。
- **開く:** 閉じるの逆順。① 開閉ボタンから左上にひとつ出る → ② 複数段のときは下へ縦に展開 → ③ 各段が横に展開する。行の高さは①②の間に広がる。

- 以前の「年のボタンが帯のボタンへ左から順に吸い込まれる」動きは、この改訂で置き換え。

- ALLで全行を同時に畳むとき、上の行の高さが先に詰まると下の行のボタンが一緒に上へ動き、開閉ボタン帯の上へ最大約100pxはみ出していた。
- ALLで畳むときは、各行のボタンが開閉ボタンに吸収されてから行の高さを畳む(個別の開閉は従来どおり)。

- 追加修正: CONTENTSは2段になることがあり、所要時間が他の行より長い(横→縦→吸収)ため、ALLで畳むと最後まで1行だけ残っていた。ALLでは最も長い行に合わせ、短い行は開始を遅らせて全行の終わりと行の畳みをそろえる。

## BADGE機能の削除
- ヘッダーの BADGE ボタン、各フィルターボタンの「押したときの件数」(`.count-badge`)、畳んだボタンの選択数(`.fold-badge`)、DISPLAY の BADGE スイッチ、ヘルプの BADGE 行を削除した。理由: BADGE をONにすると全フィルターボタンぶんの件数計算(約100回 × 全件)が走り、データ件数が多いと表示が遅くなるため(約13,000件で1操作あたり約190ms増)。
- ヘッダー右の「<」(`hdrMoreBtn`)を削除。ICON は常に直接表示する(スマホのズーム時 `zoom-wrap` も同じ)。検索行の「<」(`toolsMoreBtn`)は残す。
- PCのホバーでの件数プレビュー(`previewCountFor`)は残す。保存済みの設定に `hdr.badge` があっても無視される。

## sns の Fancam を種類(SNS)ごとにまとめる
- ビューアのsnsポップアップで、Fancam行(tagsに `Fancam` があるリンク、または type が `fancam` のリンク)を SNS の種類ごとのグループに分ける。データの変更は無し(表示だけ)。
- 種類の決め方: リンクが入っている sns の `type`(x / instagram / tiktok / youtube など)。type が `fancam` のリンクは、URLのドメインから判定する(`x.com`・`twitter.com`=X、`instagram.com`、`youtube.com`・`youtu.be`、`tiktok.com`、`cl-live.com`、`radiko.jp`、`girls2-fc.jp`)。判定できないものは ETC。
- グループの並びは SNS の表示順(X → Instagram → TikTok → YouTube …)で、ETC が最後。
- 各グループは、閉じているとき「+件数」だけを出し、押すとそのグループだけが開く(番号チップを5個ずつ。「▲」でそのグループだけ閉じる)。番号はグループごとに1から振り直す。種類のアイコンは付けない。
- 種類名(X / Instagram / ETC など)は、TAGのON/OFFに関わらず常に、押せない小さなチップで出す。閉じているときは「+件数」の右、開いているときは「▲」の右。リンクのタグはFancamでは出さない。
- 「+件数」のボタンは桁数が増えても大きさを変えない(幅40px固定)。+100以上は文字を小さくする(4文字=9px、5文字=7.5px)。
- 動画リンクのポップアップ(曲の動画のFancam)は対象外で、従来どおり。
